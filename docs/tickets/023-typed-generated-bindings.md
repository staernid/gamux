# 023 — Generate typed Wails bindings (NEEDS HUMAN DECISION, optional)

**Area:** IPC boundary · **Size:** L

## Context
Current state: `api/bindings.gen.js` (generated by `gui/bindings_manifest_test.go`,
run via `make bindings`) lists method names and arity, and `app.js` enforces
them at runtime. A Go test also checks that every `AppAPI.x` in the frontend
exists. This catches typos and wrong argument counts, but **return types
are still untyped** for `svelte-check`.

Wails v3 can generate full JS/TS bindings with JSDoc types for all Go structs
(`wails3 generate bindings`). The `wails3` CLI is not currently installed
(`go install github.com/wailsapp/wails/v3/cmd/wails3@v3.0.0-beta.27`).

## Considerations
- The generated models mirror Go JSON tags (snake_case). The frontend
  normalizers (tickets 001–005) would take those generated types as input and
  return the `types/domain.d.ts` camelCase types. That's a clean split.
- The browser/Vitest mock layer must keep working: the generated functions
  call `@wailsio/runtime` directly, so the mock swap would need to happen at
  the runtime level (Vitest `vi.mock('@wailsio/runtime')`) or behind a thin
  wrapper.
- This replaces `bindings.gen.js` and the custom manifest test. Delete them
  if you adopt this (Single Path Forward).

## Do
Ask the maintainer first. If approved: add a `make bindings` that runs
`wails3 generate bindings`, commit the output under `frontend/src/api/gen/`,
switch `AppAPI` to wrap the generated functions, and remove the hand-rolled
manifest.
